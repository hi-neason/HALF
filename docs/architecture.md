# HALF 架构草案

状态：整体架构仍为草案。当前已有 `ChatModel`、文本和工具调用内容块、请求/响应类型及可订阅的模型事件流，以及 `OpenAiChatModel`、`OpenAiResponsesModel`、`AnthropicMessagesModel` 三种完整响应和 SSE 流式适配器。`tool` 包已实现工具注册、执行和单次调用结果；下述 Agent 循环和运行级结果尚未实现。具体实现见 [LLM 接口协议](llm-api.md)、[流式接口](streaming.md) 和 [工具注册与执行](tools.md)。

官方 HTTP/SSE 的模型映射入口与完整 JSON 入口并存，具体端点和能力边界见 [官方协议覆盖](official-api.md)。

## 学习目标与依赖边界

架构服务于理解 Agent 生态的技术原理。AI 应用层逻辑使用原生 Java 实现，保持消息流转、状态变化和执行决策可以直接阅读与验证。

JDK 标准库优先；JSON 编解码、HTTP 传输等基础能力可以按需使用 Jackson 或通用 HTTP 客户端。模型适配器自行构造请求、解析响应并映射工具调用；如实现流式输出，其事件处理和增量消息组装也由项目代码负责。不使用 AI 框架、Agent 框架或模型供应商 SDK 代替这些实现，避免引入重型依赖。

外部模型服务可承担推理；本项目的自行实现范围是 Agent 应用层机制，不包含模型训练或底层推理引擎。

## Harness 的职责

模型负责生成响应与提出工具调用；harness 负责维护运行上下文、推进循环、执行已授权的工具、回填结果并判断何时停止。宿主应用负责选择模型、注册工具和配置运行策略。

## 最小职责划分

| 职责 | 输入与输出 | 边界 |
| --- | --- | --- |
| 模型接口 | 消息与工具定义 → 文本或工具调用 | 使用 Java 自编适配器转换供应商 HTTP 协议，不依赖模型 SDK |
| 消息与上下文 | 用户消息、模型消息、工具结果 | 保留消息顺序和工具调用标识，先使用内存状态 |
| 工具注册与执行 | 工具名、参数、调用标识 → 工具结果 | 只执行已注册工具，校验参数并保留调用关联 |
| Agent 循环 | 初始上下文与运行配置 → 运行结果 | 控制模型调用与工具执行顺序，落实轮次上限 |
| 运行结果 | 最终输出、上下文、停止原因 | 区分正常完成、轮次耗尽与执行失败 |

先在一个简单 Java 工程中表达这些职责。出现实际复用或发布需求后，再决定是否拆分模块。

## 计划中的 Agent 执行流程

1. 接收用户输入、历史消息、工具注册表和最大模型调用轮次。
2. 在每次调用模型前检查轮次预算。
3. 模型没有提出工具调用时，记录响应并正常结束。
4. 模型提出工具调用时，记录调用消息，按返回顺序校验并执行工具。
5. 用调用标识将每个工具结果与对应调用关联，追加到上下文，再进入下一轮。
6. 达到上限时返回明确的停止原因与现有上下文，不伪造最终答案。

初版按顺序执行工具。模型失败结束本次运行；未知工具、非法参数和工具执行异常转换为可识别的错误结果供模型处理，并仍受总轮次上限约束。错误中不泄露密钥等敏感信息。

当前 `ToolExecutor` 已提供单次及批量工具执行，支持调用上下文、进度、协作式取消、宿主详情及模型可见文本裁剪。批量调用先检查重复 ID，再按顺序执行；参数的 JSON 对象格式由执行器检查，字段和业务约束由工具实现负责。模型响应是否完整、消息历史追加和轮次预算属于后续 Agent 循环的职责。

## 最小闭环验收

- 不请求工具时，执行一次模型调用后正常返回。
- 请求工具时，工具结果保留调用标识，并可被下一次模型调用读取。
- 一次响应中的多个工具调用分别获得对应结果，顺序确定。
- 未知工具和参数错误不会执行任意代码，也不会形成无限重试。
- 达到轮次上限时不会继续调用模型或执行额外工具。
- 模型失败有明确结果，测试无需真实网络或凭据。

## 模型传输与协议边界

`model/http` 负责原生 HTTP、SSE 分帧和 `Flow` 订阅生命周期。OpenAI 与 Anthropic 各自实现认证配置、请求映射及事件解码，共享需求量、取消和超时处理。Anthropic 的内容块与事件差异见 [Messages 协议](anthropic-messages.md)。

模型入口与原始 API client 的同步调用共用 `HttpCalls`：跟踪进行中的请求、限制完整响应读取时间、关闭时取消请求，并统一检查 HTTP 状态。JSON 解码及 `HttpClient` 的关闭策略由各入口负责。

两种流式入口共用 `SseParser` 的字段解析。`ModelStream` 接收 JDK 拆分后的行并交付模型事件；原始 API 流通过 `SseFrameReader` 有界读取字符并交付原始 SSE 事件。订阅调度和协议终止判定各自保留：模型入口必须得到完整模型结果，原始 Responses 流则保留失败终态供调用方判断。

通用消息以 `ReplayState` 标明快照所属协议，快照字符串由对应适配器解释。切换协议时调用方可显式移除回放状态；内容块本身仍须满足目标协议约束，详见 [模型内容与回放](official-api.md#模型内容与事件)。
